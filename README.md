# battery-tray

Небольшая утилита для Windows 10 и 11, которая показывает заряд беспроводных устройств в области уведомлений (трее): мыши, клавиатуры, наушников, геймпада. Работает с устройствами по Bluetooth и по донглу, написана на Rust.

## Статус

Ранний прототип. Код написан, но пока не собран и не проверен на реальном оборудовании: разработка велась без доступа к Windows. Ожидайте ошибок компиляции при первой сборке, особенно в `src/sources/bluetooth.rs`, `src/sources/logitech.rs`, `src/app.rs` и `ui/popup.slint`. Если вы собрали проект и столкнулись с ошибкой, откройте issue с выводом `cargo build`.

## Зачем это нужно

Windows показывает заряд только части Bluetooth-устройств и только в «Параметрах». Устройства на донглах 2.4 ГГц (например, игровые мыши Logitech) система не показывает вовсе, для них нужна фирменная программа, которая обычно тяжелее, чем сама задача. Цель проекта: один маленький процесс, который собирает заряд из разных источников и показывает его в одном месте.

## Возможности

- Иконка-кольцо в трее с самым низким зарядом среди всех устройств (устройства на зарядке не учитываются).
- Мини-иконка в трее для каждого закреплённого устройства. Под значком устройства показывается либо полоска заряда, либо число. Режим переключается в окне.
- Всплывающее окно со списком устройств: проценты, тип подключения, сегментированная шкала заряда, анимации при открытии.
- Цвет показывает состояние: обычный, зарядка, низкий заряд (меньше 20%).
- Одно уведомление Windows при падении заряда ниже 20%. Следующее придёт только после того, как заряд поднимется выше порога или устройство поставят на зарядку.
- Автозапуск вместе с Windows, включается в меню трея.
- Сборка в один `.exe` без зависимостей от установленной среды выполнения Visual C++.

## Поддерживаемые устройства

| Источник | Что читается | Ограничения |
|---|---|---|
| Bluetooth (классический и LE) | Свойство PnP `DEVPKEY_Bluetooth_Battery` (`{104EA319-6EE2-4701-BD47-8DDBF425BBE5}`, pid 2), то же, что показывают «Параметры Windows» | Устройства без датчика заряда пропускаются. Статус зарядки через это свойство недоступен |
| Logitech на донглах Unifying, Bolt, Lightspeed | HID++ 2.0: имя устройства (фича `0x0005`), заряд (фичи `0x1004` и `0x1000`) | Нужен доступ к HID++ интерфейсу приёмника. Целевое устройство: G Pro X Superlight 2 |
| Mock | Четыре вымышленных устройства | Только для разработки, включается переменной `BATTERY_TRAY_MOCK` |

Донглы других производителей пока не поддерживаются. У каждого из них свой протокол, и для каждого нужен отдельный источник, см. раздел «Добавление нового источника».

## Требования

- Windows 10 или 11. Интерфейс рассчитан на Windows 11.
- Rust (stable) и Microsoft C++ Build Tools для цели `x86_64-pc-windows-msvc`.

## Сборка и запуск

```
cargo test                            # тесты и превью иконок в target/preview, работает на любой ОС
set BATTERY_TRAY_MOCK=1 && cargo run  # запуск с вымышленными устройствами
cargo build --release                 # target\release\battery-tray.exe
```

Release-профиль собирается с `lto`, `strip` и `panic = "abort"`. Статическая линковка CRT включена в `.cargo/config.toml`, поэтому `.exe` запускается на чистой системе.

Сборку можно доверить GitHub Actions: workflow `.github/workflows/build.yml` на каждый push запускает тесты, собирает релиз и сохраняет `battery-tray.exe` как артефакт.

## Использование

- Левый клик по любой иконке проекта открывает или закрывает окно. Окно закрывается кликом в другое место и клавишей Esc.
- Булавка в строке устройства выводит его в трей отдельной мини-иконкой. При первом запуске закреплены все устройства.
- Переключатель «Полоска / Число» в нижней части окна меняет вид мини-иконок.
- Кнопка обновления запрашивает заряд сразу. Автоматический опрос идёт раз в минуту.
- Правый клик по иконке-кольцу открывает меню: «Запускать с Windows» и «Выход». Автозапуск по умолчанию выключен.

Важно для Windows 11: новые значки трея система по умолчанию прячет в скрытую область. Чтобы увидеть иконки проекта, откройте «Параметры, Персонализация, Панель задач, Другие значки в углу панели задач» и включите `battery-tray`. Порядок значков в трее задаёт Windows, приложение на него не влияет.

## Настройки

Файл `%APPDATA%\battery-tray\config.txt`, простой текст без сторонних библиотек:

```
percent=1        # 1 - показывать число в мини-иконках, 0 - полоску
pins=custom      # признак того, что набор закреплённых устройств задан вручную
pin=bt:Keychron K3
pin=logi:PRO X 2
```

Пока файла нет, закреплены все найденные устройства. Идентификаторы устройств строятся как `bt:<имя>` и `logi:<имя>`.

## Как это устроено

```
 источники (Bluetooth, Logitech, ...)         главный поток
 ┌───────────────────────────┐   канал     ┌────────────────────────┐
 │ фоновый поток, опрос раз  │ ──────────> │ таймер 50 мс разбирает │
 │ в минуту, Vec<Device>     │             │ сообщения, обновляет:  │
 └───────────────────────────┘             │  - иконки трея         │
   клики по трею и меню ─────────────────> │  - окно (Slint)        │
                                           │  - уведомления         │
                                           └────────────────────────┘
```

- `model.rs`: структура `Device`, трейт `BatterySource`, уровни заряда и цвета.
- `render.rs`: рисует иконки трея в памяти. Кольцо и полоска строятся через `tiny-skia`, значки устройств рендерятся из SVG через `resvg`, цифры выводятся встроенным шрифтом 3x5 пикселей. Размер иконки 32x32.
- `sources/`: по одному файлу на источник данных. Каждый реализует `BatterySource::poll`.
- `config.rs`: чтение и запись настроек.
- `app.rs`: цикл событий, трей, окно, автозапуск, уведомления. Состояние UI живёт в главном потоке, остальные потоки только присылают сообщения.
- `ui/popup.slint`: описание окна и его анимаций.
- `dump.rs`: диагностика HID, см. ниже.

Структура репозитория:

```
assets/        SVG-иконки (Lucide)
src/
  main.rs  app.rs  config.rs  dump.rs  model.rs  render.rs
  sources/     bluetooth.rs  logitech.rs  mock.rs
ui/popup.slint
build.rs       компиляция .slint только под Windows
.cargo/config.toml
.github/workflows/build.yml
```

## Добавление нового источника

1. Создайте `src/sources/<бренд>.rs` и реализуйте `BatterySource`: метод `poll` возвращает `Vec<Device>` (идентификатор, имя, тип, подключение, процент, признак зарядки).
2. Подключите модуль в `src/sources/mod.rs` под `#[cfg(windows)]`.
3. Добавьте источник в список `sources` в функции `poll_loop` в `src/app.rs`.

Если протокол донгла неизвестен, начните с диагностики.

## Диагностика донглов

```
battery-tray.exe --dump-hid              # список всех HID-интерфейсов в hid-dump.txt
battery-tray.exe --dump-hid 258A:0001    # то же, плюс feature-отчёты и 20 секунд входящих данных
```

Второй запуск нужен для устройств, чей протокол неизвестен. Пока идёт запись, понажимайте клавиши и Fn-комбинации, подключите зарядку, чтобы данные менялись. Файл `hid-dump.txt` создаётся в текущей папке. Приложите его к issue, и по нему можно искать байт с зарядом.

## Известные ограничения

- Окно позиционируется над иконкой, поэтому подходит только панель задач внизу экрана. Для панели сверху или сбоку положение окна будет неверным.
- Ширина экрана берётся с основного монитора, на нескольких мониторах возможны сдвиги.
- Заряжается ли Bluetooth-устройство, Windows через используемое свойство не сообщает.
- Устройства с одинаковыми именами считаются одним устройством.
- Донглы, не отдающие заряд в компьютер, показать невозможно ни в каком виде.
- Приложение не подписано, поэтому SmartScreen может показать предупреждение при первом запуске скачанного `.exe`.
